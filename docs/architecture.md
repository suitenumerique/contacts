# Architecture

La Suite Contacts is the Suite's **contacts app**: personal address book,
labels, groups, trash, vCard/CSV import-export.

People/group suggestion across the Suite (sharing modals in Docs, recipient
fields in Messages, attendee pickers in Calendars) is **not** this app's job:
it belongs to the standalone **directory** service, which aggregates every
source Suite-wide. Contacts is **one of its sources**:
the directory service reads this app's contacts and groups over a service
channel (`contacts:read` / `groups:read`), so a user's saved contacts surface
wherever the Suite suggests people.

```
                                       ┌─────────────────────────┐
   Docs / Messages / Calendars ... ──▶ │   directory service     │
                                       └───────────┬─────────────┘
                                                   │ reads as one source
                                                   │ (X-Channel-Id / X-API-Key)
                 ┌─────────────────────────────────▼───┐
   Contacts UI ─▶│  contacts app                       │
                 │  GET /contacts/  GET /groups/       │
                 └─────────────┬───────────────────────┘
                               ▼
                            local PG
                         contacts + groups
```

## Components

- **Backend** (`src/backend/`): Django 5 + DRF, PostgreSQL, Redis,
  dramatiq worker (async vCard/CSV imports). Three ways in: OIDC login for
  people (Keycloak in dev, via `django-lasuite` / `mozilla-django-oidc`),
  [channel](channels.md) API keys for services, and HTTP Basic Auth with a
  channel password for [CardDAV](carddav.md) clients.
- **Frontend** (`src/frontend/`): React 19 + Vite + TanStack Router/Query +
  `@gouvfr-lasuite/ui-components`; pnpm via corepack; oxlint/oxfmt. Three
  panes (sidebar, list, detail); the open contact or group, the search and
  the filters are all in the URL (`/contacts/{id}?q=&label=&favorites=1`,
  `/groups/{id}`, `/trash/{id}`). The API client is generated by orval.

## Domain model (core app)

| Model                     | Purpose |
| ------------------------- | ------- |
| `Organization`            | Tenant; `external_id` from a configurable OIDC claim (`siret`) or the email domain, see [organizations.md](organizations.md). |
| `User`                    | OIDC-provisioned account, belongs to one organization. |
| `Contact`                 | vCard-ish card. `scope` says whose it is: `personal` (its `owner`'s) or `organization` (the organization's curated address book, no `owner`; a database constraint ties the two). Who sees a row is `Contact.objects.visible_to(user)`, who writes it `Contact.is_writable`: its owner, or for an organization row the organization's administrators (`can_admin`); a row from a `source` is read-only. `created_by` / `updated_by` record who wrote it. `overlay_of` + `overridden_fields` hold a user's local **overlay** merged on top of a contact they cannot edit (created via `POST /contacts/{id}/fork/`); deleting that contact for good detaches the overlays into personal contacts. Multi-valued props (emails, phones, ...) are JSONB `{type, value}` lists; unmodeled vCard props survive in `vcard_extra`. Names follow vCard: `full_name` is `FN` (the only name required, filled from the parts when blank), the `N` parts and `nickname` are optional; the list is sorted by family name, or by full name when there is none. |
| `ContactLabel`            | Per-user colored labels (libellés); a predefined set is seeded when the user is created. |
| `ContactGroup` (+membership) | Named sets of contacts, scoped like contacts. A personal group is its owner's; an organization group is visible to the whole organization and edited by its administrators (`can_admin`, see [entitlements.md](entitlements.md)), and only holds contacts the whole organization sees; one from a `source` is read-only. Groups are never overlaid. |
| `Channel`                 | Service API keys, see [channels.md](channels.md): how the directory service and CardDAV clients authenticate to this app. |

Search uses a denormalized `search_text` column, stored lowercased and
accent-folded (`core.utils.strip_diacritics`). The query is folded the same
way and matched word by word with a case-sensitive `contains` (`LIKE`), which
the `pg_trgm` GIN index on `search_text` serves; `icontains` would compare
`UPPER(...)` and skip the index.

Phone numbers are indexed as digit strings (`core/phones.py`): as written,
international (`33639986309`) and national (`0639986309`), read with
libphonenumber. Numbers written without `+` are read as numbers of
`CONTACTS_PHONE_DEFAULT_REGION` (default `FR`). A query made only of digits
and phone separators is looked up as one run of digits, so `06 39 98`,
`+33 6 39` and `0033639` all find `+33 6 39 98 63 09`.

The `carddav` app (`src/backend/carddav/`) exposes the same rows over
[CardDAV](carddav.md), reusing `Contact.is_writable`. Its own tables only
hold sync bookkeeping (a change journal numbering every write to a contact,
so a client's delta cannot silently miss one).

## Key flows

- **Search**: `GET /contacts/?q=` over the denormalized `search_text`,
  serving the header search. Consumed by the directory service too,
  over a `contacts:read` channel.
- **The organization's address book**: administrators create organization
  contacts and groups (`is_org_contact` / `is_org_group` at creation),
  import a file into it (`scope=organization` on the import endpoints), and
  copy one of their own contacts into it (`POST /contacts/{id}/share/`:
  everything but notes and labels; their contact then goes, or stays as a
  local copy holding its notes and labels). Organization contacts carry no
  labels yet.
- **Read-only rows & overlays**: rows a user cannot edit (the
  organization's, for a non-administrator, and those from a `source`) can
  be overlaid: `POST /contacts/{id}/fork/` creates a personal overlay
  storing only the fields the user changed, so untouched fields keep
  tracking the original.
- **Trash (corbeille)**: the first `DELETE /contacts/{id}/` sets
  `deleted_at`, `GET /contacts/?trash=true` lists the user's trashed rows
  (plus the organization's, for an administrator),
  `POST /contacts/{id}/restore/` brings one back, a second `DELETE` is
  permanent. `purge_trashed_contacts` hard-deletes rows trashed for longer
  than `TRASHBIN_CUTOFF_DAYS` (default 30), and `purge_carddav_changes`
  drops the sync tombstones that outlived them. Both have to be scheduled,
  see [Scheduled jobs](#scheduled-jobs).
- **Import/export**: `POST /contacts/import-vcf/` or `import-csv/` queues a
  dramatiq task, polled with `GET /tasks/{id}/`. A card matching one of the
  user's own contacts is skipped: the match is on any email address, or for
  a card without email, on first + last name (or the full name when there
  is neither) and the digits of the first phone. Trashed contacts count as
  matches, and a matched trashed contact is restored, so re-importing a
  file creates nothing new. vCard `CATEGORIES` become labels, except the
  system groups of a Google Contacts export (`myContacts` is dropped,
  `starred` makes a favorite; same for the CSV `Labels` column), and group
  cards (Apple's `X-ADDRESSBOOKSERVER-KIND:group`, or vCard 4 `KIND:group`)
  become groups, merged into a personal group of the same name, with the
  members their UIDs name in the file or among the user's contacts. Export via
  `GET /contacts/export-vcf/` or `export-csv/` (`core/services/csv_service.py`
  documents the CSV columns).

## Scheduled jobs

Two management commands have to run daily. Nothing in the app schedules
them.

```
python manage.py purge_trashed_contacts
python manage.py purge_carddav_changes
```

- **Scalingo**: `cron.json` at the repository root declares both.
- **Kubernetes**: one `CronJob` per command, using the backend image and
  the same environment as the backend `Deployment`:

  ```yaml
  apiVersion: batch/v1
  kind: CronJob
  metadata:
    name: contacts-purge-trashed-contacts
  spec:
    schedule: "0 3 * * *"
    concurrencyPolicy: Forbid
    jobTemplate:
      spec:
        template:
          spec:
            restartPolicy: OnFailure
            containers:
              - name: purge
                image: ghcr.io/suitenumerique/contacts-backend:<version>
                command: ["python", "manage.py", "purge_trashed_contacts"]
                envFrom:
                  - secretRef:
                      name: contacts-backend  # same env as the backend
  ```

  and the same with `purge_carddav_changes` (e.g. at `30 3 * * *`).
